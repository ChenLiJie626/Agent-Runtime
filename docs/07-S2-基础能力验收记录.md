# S2 基础能力验收记录

日期：2026-09-25。验收依据为 [SPEC 000](../specs/000-runtime-kernel.md) 的 KC-01 至 KC-13。这里的抽象规则、固定材料后端和合成 SDK 探针只验证基础包机制，不代表真实程序缺陷检出率。当前 **13 项均通过，S2 基础能力门禁完成**。

## 可复现命令

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python tools/smoke_foundation_runtime.py --output .poc/foundation-runtime-smoke.json
.venv/bin/python tools/smoke_session_recovery.py --output .poc/foundation-session-recovery-smoke.json
```

后两条命令需要本机 CC Switch 的有效回环路由和 Claude Agent SDK 可选依赖。脚本读取本机生效的 Claude 路由配置，不把认证值写入报告。基础包探针取得两个独立 SDK session、结构化 Claim/Assessment 和已保存证据；验证者保留未知项时评价器返回 `inconclusive`，见[基础包报告](../.poc/foundation-runtime-smoke.json)。恢复探针实际识别缺失 transcript，记录 `SessionUnavailable` 和完成的 Transition，以新 SDK session 从 Handoff 保存 Claim，见[恢复报告](../.poc/foundation-session-recovery-smoke.json)。另一个[SDK 协议探针](../.poc/claude-sdk-smoke-cc-switch-gpt6-version.json)记录了显式 resume、新会话、结构化输出、自定义 MCP 工具和设置隔离。输出里的 `claude-sonnet-5` 是本地路由别名，单凭该字段不能证明上游实际模型。
