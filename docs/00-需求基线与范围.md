# agent-runtime 需求基线与范围

状态：**基础能力范围已重整；0.2.0 本地发行线已按通用契约验证** · 2026-09-25。依据：[原始交接文档](../Claude_Agent_SDK_Agent层开发交接_精简版_v1.1.md)；当前门禁以[规格导航](../specs/README.md)和[SPEC 000](../specs/000-runtime-kernel.md)为准，技术选型见[ADR 010](04-最终架构决策-ADR.md)，阶段状态见[S3 验收记录](09-S3-验收记录.md)。

## 产品定位

`agent-runtime` 是供其他项目导入并扩展的**程序缺陷挖掘基础包**。调用方提供固定分析快照、缺陷规则与候选身份策略、程序查询后端、规则裁决器和模型运行配置；基础包返回带证据、覆盖限制和恢复信息的候选结论。Base/Head 对比与 C/C++ 只是可选规则的输入形态，基础包不自带完整静态分析器。

此前使用的“Head 新增空返回”场景保留为[SPEC 001](../specs/001-defect-runtime.md)和[SPEC 005](../specs/005-golden-cases-and-oracles.md)的**后续规则插件示例**。当前 S2 用抽象测试规则验证基础包机制，不要求内核证明该场景的程序语义。

## 使用者与扩展点

| 使用者 | 需要完成的事 | 基础包责任 |
|---|---|---|
| 规则作者 | 描述缺陷条件、必查项、反证与发布门槛 | 校验规则版本、依赖、能力和冲突；固定运行 Profile |
| 分析工具集成者 | 接入 Joern、Clang、CodeQL 或内部服务 | 统一查询请求、来源、覆盖与错误语义；先存原始材料再返回引用 |
| Agent 开发者 | 自定义调查与验证角色、Prompt、Skills、模型 | 角色协议与最小上下文；会话及结构化输出验收 |
| 审核者/上层产品 | 判断缺陷是否可信、哪里未查完 | 证据链、反证、结论条件、覆盖分母和失败原因 |

## 必须满足的需求

### R1 任务与规则

- 每次分析固定：仓库标识、源码/构建范围及其摘要、规则/Profile 版本、工具版本和允许范围；需要差分分析的规则再固定 Base/Head。
- 规则把一个候选展开为它自己的必查问题，基础包不固定检查名或数量。问题状态分别为未查、查询中、已查且有证据、部分覆盖、失败/不支持；不能用“已调用工具”代替“已完成”。
- 候选身份由规则提供的规范化策略决定，须足以区分相关对象、位置、路径与构建变体；身份不足时不得做跨会话永久排除。相邻候选不可互相排除。
- 任务可由确定性规则、静态工具或 Agent 提议，但新候选入库前要去重、绑定快照并注明发现来源。

### R2 多角色协同

- **候选发现/任务规划**优先由规则与工具完成；必要时 Agent 只提出候选或查询建议。
- **调查者**负责构造触发假设、按缺口查询、列出证据/反证/未知。
- **独立验证者**在独立会话中主动找反例，核对规则所要求的触发条件、对象与路径前提；它不自动继承调查者的主观结论。
- **VerdictGate** 是普通程序，校验引用、版本、必查项和结果语义。两个 Agent 的一致意见本身不是证据。
- 可注册**有明确输入/产出、工具授权与失败语义的专项角色**；默认提供调查者与独立验证者，不按每个检查项盲目创建一个 Agent。

### R3 证据与判断

- 原始 Evidence 不可由模型伪造 ID；需保留原文或可重放材料、来源位置/哈希、查询参数、版本、覆盖范围、限制和查询状态。
- Claim 是带前提的主张；Assessment 是验证者的判断；两者与 Evidence 分存。引用不存在、过期、跨快照、跨候选或内容哈希错误时拒绝确定结论。
- 查询状态至少有 complete、partial、timeout、failed、unsupported、denied。空结果需给出“搜索全集/覆盖边界”才可作为负证据；部分结果不代表不存在未见对象或路径。
- 结论为 confirmed、refuted、inconclusive。confirmed 要列出可同时成立的触发条件和证据范围；refuted 要有该候选的具体反证；其他情形为 inconclusive。执行成功/失败与结论状态分开。

### R4 SessionService 与恢复

- 区分 Analysis、CandidateTask、RoleAttempt、SDKSession、Checkpoint 与 Transition。一个 SDK 历史同一时刻只能有一个写入者。
- 显式 `resume` 仅用于同一 SDK 历史续查，并在恢复前核对固定快照、规则/Profile、工具授权与会话归属；不同则拒绝或开启新分析。
- `rotate` 在安全结束点保存经校验交接包，再启动**新** SDK 会话；记录新旧 ID 映射并保留旧历史。不把 fork 当压缩，不修改 SDK 内部 JSONL。
- 进程崩溃后，系统从持久化任务/事件/证据恢复。工具调用采用请求幂等键；“请求已发但结果未记录”标为待核对，不能直接当完成或盲目重放有副作用的工具。
- 支持尝试次数、预算、超时、取消、失败重试和事件序号；同一候选的确定结论幂等返回，inconclusive 可显式重新打开并记录原因。执行器能力须真实声明；不可用的中断、事件流或用量不可假装支持。

### R5 缺陷专用 ContextManager

- 分离四层：**原始材料**（长期、不可改）、**证据关系**（事实/假设/反证）、**本轮工作集**（随缺口动态选择）、**交接包**（跨会话最小完整状态）。摘要永远不是新 Evidence。
- 工作集按“当前还缺哪个条件”选择规则相关代码、对象、路径、配置或其他证据。长日志按查询结论、失败原因和定位分段；重复代码去重，但保留影响逻辑的条件、否定词与定位。截断必须显式标注，并能取回原文。
- 交接包至少含：固定快照/Profile、候选精确身份、目标、已证事实及引用、假设、前提、反证及其作用范围、已查/未查项、未知与查询限制、排除记录、事件范围、下一步。
- 交接验证检查**不丢条件、不丢反证、不丢未查项、不把 partial 改成 complete**。未知项若被解决须记录解决证据；不允许无痕删除。
- 已排除候选的记录是带证据与作用域的 `ExclusionRecord`。同一固定快照的新会话必须读取并抑制重复误报；输入、构建、规则、证据依赖变化时记录过期原因并重新验证。排除一个候选不能宣称其邻近候选也安全。

### R6 安全、观测与质量

- 默认只读；分析仓库的注释、配置、提示文本均视为数据。工具允许列表和文件/网络/凭据隔离由实际执行环境共同保证，不能只靠 Prompt。
- 记录每轮模型、工具、时间、可用的用量/成本、失败与覆盖。报告必须同时呈现已发现候选数、已完成数、未完成数，以及“未发现集合仍未知”这一覆盖边界。
- 形成正例、反例、证据不足、工具失败、跨会话、版本漂移的回归集；真实静态后端与真实模型联测结果另行标注，模拟测试不可冒充实际准确率。

## 非目标与优先级

当前不做指定缺陷规则的详细语义证明、完整 CPG/PDG 自研、自动修复、分布式多 Worker、向量数据库、无边界并行 Agent 或真实漏洞自动发布。空返回与 CUDA/AscendC 异步生命周期可作为后续 Rule/Profile 和工具后端扩展。

P0：R1–R6 的可复用纵向链路、可恢复证据、规则/查询/执行器替换及真实 Agent SDK 协议联调；P1：发行与第三方接入、更多专项角色；P2：指定规则插件、真实语义后端和项目回归评测。真实语义后端 PoC 可继续探索，不构成 P0 门禁。

## 尚需确认的产品决策

以下部署输入需要在具体项目集成时确定：目标仓库权限、是否允许构建/执行目标代码、源码能否发送到外部模型、运行环境与数据保留期限、模型认证和费用上限，以及所选静态工具的许可。它们不阻塞本地基础包开发；未确定时按“只读、最小权限、本地证据、可替换后端”设计。
