# 开源调研与复用决策

调研日期：2026-09-25。本文是最初以空返回场景评估开源项目的**历史调研**；其中“尚未联调”描述调研当时状态，后续实测见[PoC 记录](06-S2-纵向PoC记录.md)。当前基础包范围与门禁以[规格导航](../specs/README.md)和[ADR 010](04-最终架构决策-ADR.md)为准。可引用 Agent runtime 的架构细节另见[专项调研](03-Agent-Runtime开源架构调研.md)。

## 选择标准

当时选取的探索场景是 **C/C++ 增量缺陷检查**：Head 中新增可空返回，影响未修改的调用者。该场景现在属于后续[SPEC 001](../specs/001-defect-runtime.md)规则插件。基础包当前优先验证可替换端口、证据与状态恢复；通用“多 Agent”数量不作为优势指标。

## 当前决策

1. **不重造静态分析引擎。** 定义规则无关的 ProgramQuery 契约；Joern PoC 的 `调用者 → 参数传播 → 返回值 → 解引用 → 保护条件` 用于后续空返回插件。查询结果必须写明覆盖范围与局限。
2. **不复刻大型多 Agent 平台。** 基础包只承担任务分解、角色隔离、状态恢复、证据账本、缺陷专用上下文和程序化验收。模型运行通过 SDK 适配器接入。
3. **插件实施时再选择语义后端。** 已有 Clang/Joern PoC 作为空返回规则的探索材料；后续比较跨文件正确率、编译配置、输出定位、部署和维护成本。基础包 S2 不要求选定真实语义后端。
4. **许可边界落实到插件形态。** 基础包的许可由项目另定；CodeQL CLI、GPL-3.0 的 codebadger 和 AGPL-3.0 的 Vulnhuntr不嵌入核心发行物。是否作为外部服务集成，需结合发行方式核实许可。
5. **Claude SDK 执行与业务 runtime 分层。** SDK 管模型工具循环，本包管候选、证据、角色、任务检查点与上下文。首版不依赖通用工作流框架；各项目的可复用模式及限制详见[专项调研](03-Agent-Runtime开源架构调研.md)和[ADR 010](04-最终架构决策-ADR.md)。

## 后续空返回插件的实证问题（非基础包 S2 门禁）

| PoC | 通过条件 |
|---|---|
| C/C++ 构建快照 | Base/Head 在同一编译参数下可分析；缺失配置显式失败。 |
| 跨文件空返回 | 识别 `process(0)` 路径与 `guardedProcess` 的排除条件，列出未解析调用。 |
| 证据定位 | 每项语义判断能回到提交、文件、行或图节点及原始查询输出。 |
| 恢复与成本 | 重启后查询不重复产生误报；记录索引/查询时间及资源消耗。 |
| 许可与部署 | 确认目标仓库类型、后端部署方式、分发方式是否相容。 |
