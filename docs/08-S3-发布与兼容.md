# S3：公开扩展 API、发行验证与兼容策略

日期：2026-09-26。验收依据为 [SPEC 007](../specs/007-release-and-extension.md)。本地发行线为 `0.2.0`，采用 [MIT 许可证](../LICENSE)；构建和安装验证不等于已发布到包索引。

## 第三方接入路径

从 `agent_runtime` 根入口导入公开类型和函数；可选 Claude/Joern 适配器从 `agent_runtime.adapters` 导入。一个应用通常按下列顺序调用：

1. 实现 `CandidateDiscoverer`、`RuleEvaluator`、只读 `ProgramQuery` 和 `AgentExecutor`，并定义 `RuleSpec` 的必查项。发现器返回精确 `CandidateIdentity` 和每项检查的有界 `EvidencePlan`；评价器用 `decision_input_digest(...)` 生成 `RuleDecision.input_digest`；后端用 `bytes_digest(raw)` 填写完整覆盖的 `Coverage.basis_refs`。
2. 创建 `FixedSnapshot`，其中 `rule_profile_digest=analysis_profile_digest(rule, profile=..., check_planner=...)`；创建 `SQLiteStore`、`DefectRuntime`，注册评价器，再 `create_analysis`。
3. 用 `CandidateIdentity` 或身份策略提出精确候选；用结构化 `QueryRequest` 调用后端。规则/应用解释已保存的 Evidence 后，明确记录 `FactAssessment` 与 `CheckItem`。查询成功或零结果本身不会自动完成检查。
4. `RoleCoordinator.run_candidate` 依 Profile 启动独立角色；评价器和通用门禁生成裁决。`get_report` 只统计已发现候选；未提供的用量为 `usage.status=unavailable`。
5. 重开存储时重新注册需要运行的评价器与规划器。已提交的报告、Evidence 与 Exclusion 可从存储读取；精确排除仍受快照、规则版本和证据摘要约束。

`AnalysisPipeline` 已封装第 2 至第 4 步。内置 `CppUnreachableDiscoverer`、`CppUnreachableEvaluator`、`EvidenceReviewExecutor` 和 `FrozenSourceProgramQuery` 可直接组合；`CompositeProgramQuery` 将多个操作不重叠的只读后端路由为一个后端绑定。第三方实现相同 Protocol 后可逐项替换，无需修改 Runtime 内核。可运行示例见 [`cpp_unreachable_pipeline.py`](../examples/cpp_unreachable_pipeline.py)。

完整可运行的[包外样例](../examples/external_consumer.py)只从公开入口导入，提供两条抽象规则、两个不同操作 schema 的查询后端与独立角色执行器。它验证扩展接线，不表达真实缺陷语义。

## 公开边界

| 保证的 0.2.x 入口 | 用途 |
|---|---|
| `RuleSpec`, `CheckDefinition`, `FixedSnapshot`, `CandidateIdentity`, `Profile`, `RoleDefinition` | 定义固定分析范围和角色/检查。 |
| `CandidateDiscoverer`, `DiscoveryInput`, `DiscoveredCandidate`, `EvidencePlan` | 从固定 Base/Head 输入发现精确候选并声明有界取证计划。 |
| `ProgramQuery`, `ProgramResult`, `QueryOperation`, `QueryRequest`, `Coverage`, `EvidenceRef` | 定义结构化只读查询、原文和覆盖。 |
| `RuleEvaluator`, `RuleDecision`, `decision_input_digest` | 注入确定性语义裁决，接受通用证据门禁。 |
| `AgentExecutor`, `AgentCapabilities`, `RoleRunRequest`, `RoleRunResult`, `RoleCoordinator` | 接入任意执行 SDK 或固定测试执行器。 |
| `AnalysisPipeline`, `PipelineRunResult`, `PipelineCandidateResult` | 组合发现、查询、持久化、角色和裁决，并保留未执行候选。 |
| `CppUnreachableDiscoverer`, `CppUnreachableEvaluator`, `EvidenceReviewExecutor` | 随包提供的 C++ 发现、保守裁决和确定性 Evidence 审查实现。 |
| `SQLiteStore`, `DefectRuntime`, `SessionService`, `ContextViewBuilder` | 本地业务状态、会话与上下文。 |
| `canonical_json`, `digest`, `bytes_digest`, `analysis_profile_digest` | 规范 JSON、身份/原文摘要及固定 Profile 绑定。 |

完整名单以 `agent_runtime.__all__` 为准。`agent_runtime.codec`、`agent_runtime.coordinator._ScopedTools`、SQLite 表、投影 JSON 与适配器内部选项不是公开扩展 API。可选 Claude 依赖由 `defect-agent-runtime[claude]` 安装；核心导入无需它。未开放的事件流、中断和用量上报在能力声明中保持 false，要求这些能力的 Profile 会在执行前失败。

## 版本与持久数据

### 固定源码查询

S4 新增 `agent_runtime.adapters.FrozenSourceProgramQuery(snapshot, sources)`。应用传入 `{仓库相对路径: UTF-8 文本}`，并用 `FrozenSourceProgramQuery.source_digest(sources)` 绑定 `FixedSnapshot.source_digest`。构造器复制输入；`read_source` 操作只返回指定文件的 `start_line/end_line` 精确窗口，默认不超过 200 行或 16 KiB，超限要求缩小查询。快照、策略、路径选择器和内容摘要不匹配时拒绝；不读取宿主文件，不执行源码。

该后端的 `complete` 仅指文字窗口完整。规则的构建、宏、调用关系、路径等检查必须由对应后端另行完成。集成入口见 [SPEC 009](../specs/009-public-source-runtime-integration.md)与 [`run_s4_runtime.py`](../tools/run_s4_runtime.py)。

`ClaudeConfig.role_timeout_seconds` 是新增的可选参数，默认 `None` 保持原行为；设置后限制单次角色调用，包括工具等待与结构化输出。超时结束该 SDK 调用并由协调器记录保守裁决，评测另计 `timeout`。这不是已开放的实时中断接口，`interrupt` 能力仍为 false。

### 兼容要求

- `0.2.x` 的 patch 更新不得破坏上述公开符号、签名和已经声明的语义；破坏性公开 API 改动至少升下一个 minor。包版本不决定业务事件封套版本。
- 当前写入 `schema_version={"major":1,"minor":1}`。读入接受 `1.0` 与 `1.1`；未知 major、非法 minor 和未来 minor 拒绝。旧 `1.0` 事件/投影可以重建，继续写入的新事件使用 `1.1`。兼容测试在 [test_s3_compat.py](../tests/test_s3_compat.py)。
- 对持久记录的破坏性格式变化必须升 major，附迁移工具或明确拒绝读取。旧 `AnalysisSnapshot`、`CandidateKey` 和空返回示例作为当前兼容入口保留；新规则应使用通用模型。
- 异常类别是可依赖的失败分类；异常文本不是稳定 API。报告的 `schema_version` 独立标示报告形状。原始 SDK 消息、模型别名和账本事件不能代替已验证 Evidence。

## 本地发行验证

```bash
uv build --offline --out-dir dist/s3
.venv/bin/python tools/verify_s3_release.py \
  --wheel dist/s3/defect_agent_runtime-0.2.0-py3-none-any.whl \
  --sdist dist/s3/defect_agent_runtime-0.2.0.tar.gz \
  --output .poc/s3-release-verification.json
.venv/bin/python -m unittest discover -s tests -q
```

验证器检查 wheel/sdist 内容、`py.typed`、适配资源、MIT 许可证全文和元数据，以及核心无 Claude 强制依赖；在仓库外创建干净环境安装 wheel，再运行第三方扩展样例和内置 C++ Pipeline 样例。当前 S4 [验证报告](../.poc/s4-release-verification.json)通过：两个外部规则、两个外部后端、两种裁决、重开存储报告、精确 Exclusion 和源码发现 Pipeline 均成功。发行到包索引尚未执行。
