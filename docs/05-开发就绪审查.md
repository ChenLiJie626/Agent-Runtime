**S2 基础能力的 KC-01 至 KC-13 均已通过。** 逐项状态、运行命令及边界见 [S2 验收记录](07-S2-基础能力验收记录.md)。两条抽象规则与可控后端在同一运行时通过测试；有效排除在重开存储的新协调器中复用。Claude SDK 经 CC Switch 的协议探针、包入口合成规则联调与丢失 transcript 恢复联调通过；验证者保留未知项时，保守裁决为 `inconclusive`。这些结果只证明基础机制，不证明真实缺陷检出能力。Joern/Clang 空返回语义证明和 F-08 专项案例属于后续规则插件。

## S3 与 S4 的分界

S3 交付可被第三方引用的发行物：公开接口、版本与迁移策略、第二规则及第二查询后端的包外接入样例、安装验证。S3 本地验收与 MIT 许可证元数据门禁均已通过；尚未发布到包索引。

S4 已按 [SPEC 008](../specs/008-defect-quality-evaluation.md)实现公开 C++ manifest、输入摘要验证、运行结果完整性检查和统一指标报告的首版，并以 no-findings 负对照验证漏检会保留在分母；状态见[实施记录](10-S4-质量评测实施记录.md)。下一步扩大保留集并分别推进指定缺陷规则和真实项目：例如 SPEC 001/005 的 C/C++ 空返回规则、Joern/Clang 语义后端、F-08 规则专项跨会话案例和误报/漏报评测。已有[专项 PoC 记录](06-S2-纵向PoC记录.md)继续保留，但它不改变基础包的验收顺序。
