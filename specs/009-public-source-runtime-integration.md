# SPEC 009：公开源码与 Runtime 分析闭环

状态：首版集成门禁、隔离构建记录与 build-aware Joern partial Evidence 回放通过，完整语义与质量门禁未通过 · 2026-09-26。承接 SPEC 008 Q-01/Q-02/Q-04；保持 SPEC 000 的通用基础包范围。验收见[公开源码闭环记录](../docs/11-S4-公开源码Runtime闭环验收.md)。

## 目标与边界

把公开 C++ 固定源码上的候选发现接入现有证据、角色、Session、裁决和质量报告。源码查询适配器可供其他规则复用；候选发现与评价器继续由应用注入。首版沿用文本候选作为输入，保留未查的语义条件，不要求基础包内置某类缺陷算法。

源码窗口返回 `complete` 只表示精确窗口全部返回；不表示项目构建、预处理、控制流或语义取证完成。窗口 Evidence 和 `tool_observed` Fact 只能证明文字可读。缺少语义后端时，不发布 `confirmed/refuted`，不生成 Exclusion。

## 契约与验收

| ID | 要求 | 验证方式 |
|---|---|---|
| RI-01 | 分析边界只接收预先允许的项目/提交、归档和源码路径；golden、评审意见、修复标签在裁决后才参与匹配 | 标签污染测试；检查 Snapshot/Context/角色输入不含标签 |
| RI-02 | 源码后端绑定内容摘要、快照、策略和范围；只读内存文本，不执行上游代码 | 内容篡改、跨快照/路径/策略与超限拒绝测试 |
| RI-03 | 原始窗口持久化为内容寻址 Evidence；Fact、Check 和角色引用绑定同一 Task | 原文摘要检查与通用 runtime 门禁 |
| RI-04 | 调查与独立验证分别创建 Attempt/Session；记录实际 Evidence 读取、Prompt 摘要及失败类型 | 确定性控制运行与真实 SDK 运行分别报告；不能把控制执行器称为模型效果 |
| RI-05 | 未执行、SDK 错误和超时分别计数；角色调用超时、候选上限与查询执行上限可控制 | 预算/失败/超时回归；Token/实际上游不可得则显式标记 |
| RI-06 | 语义未知不因模型自信或源码窗口 complete 被消除 | 过度自信角色回归；保持 `inconclusive` 与未查 Check |
| RI-07 | SQLite 重开后报告一致；导出结果通过 SPEC 008 运行校验和报告生成 | 公开样本的持久恢复、分阶段 JSON/Markdown 报告 |
| RI-08 | 外部语义探针须先核对 manifest、样本、commit、源码归档、CPG 模式、候选位置和原文摘要；不完整构建的结果只能登记为 partial Evidence | 篡改原文拒绝回归；两角色读取同一摘要；Check 保持 `partial/unknown` |
| RI-09 | 构建执行须逐条使用 manifest 命令，绑定容器镜像、包清单、标准输出/错误和编译数据库摘要；禁网、无宿主凭据且构建失败仍形成可验证报告 | 安全解包与路径穿越回归；构建报告重载、摘要篡改拒绝；失败状态进入 Runtime 覆盖分母 |
| RI-10 | S4 的发现、查询、评价和角色执行须由公开 Runtime 扩展实现，并可经统一 Pipeline 组合；第三方实现相同端口时无需修改内核 | 内置组件端到端确认/反证/弃判测试；组合后端路由；候选预算保留测试；包外示例 |

## 实施顺序

1. 通用 `FrozenSourceProgramQuery` 及确定性失败/范围回归。
2. 应用入口连接公开归档、可替换发现插件、Runtime 与离线评分；控制运行验证传输契约。
3. 通过现有 CC Switch 路由运行真实 Claude SDK 两角色，保存成功或失败的原始状态。
4. 已在固定 Ubuntu 22.04/Clang 14 容器中禁网执行 Tesseract 的 manifest 命令，保存 183 项包清单和 216 个翻译单元的编译数据库。目标在 `hocrrenderer.cpp:503` 编译失败，因此分析状态为 `build_failure`。
5. 已提交与容器实际 183 项包清单一致的依赖锁，并用该编译数据库和完整验签源码生成 build-aware Joern CPG；验签后的查询原文通过 `ProgramQuery` 登记为 Runtime partial Evidence，调查者和验证者均读取该 Evidence。构建失败使翻译单元覆盖保持 0/216，不能据此确认缺陷。下一步解决或替换不可构建样本，再接入规则 Oracle。扩大保留集后完成 SPEC 008 完整门禁。
6. 已把 S4 工具内的词法发现、保守评价、确定性 Evidence 角色与 recorded-Joern 回放迁入公开包，并新增 `AnalysisPipeline`、组合后端及第三方端口。工具入口继续负责 manifest 下载、离线评分和报告生成。

预算中的 Token 上限首版不可强制，报告必须显式注明；SDK 费用字段也未开放。声明的墙钟预算只约束角色调用，不包括下载、发现和数据库操作。实际上游模型若网关未回传，则记录 `unavailable`，不能将角色别名当作已核验的模型身份。这些运行属于实验性集成证据，不作为同预算发布放行成绩。
